# 立式多段泵浦選型

## STOP：先檢查產品證據

只要任務要求 APP Arwana／BNF 的級數、馬達 kW、型號或候選，而對話中沒有附上可辨識版本與頻率的官方性能曲線，就立即停止產品推定。不得用經驗值、相似品牌、比例推算、budgetary selection 或語氣保留來繞過此限制。

此時必須逐字表達下列核心結論，可在不改變意思下補充內容：

> 目前只能建立水力需求規格；沒有 BNF 官方性能曲線，不能判定葉輪級數、馬達 kW、具體型號或優先候選。

禁止出現未有曲線支持的數字級數、kW 範圍、候選型號，以及「最合理」「優先」「暫估」「約」「budgetary」等產品推定。即使使用者要求初選，也不得放寬。

## 工作流程

1. 收集設計流量 Q、總揚程 H、介質、溫度、比重、黏度、pH、固體含量、吸入條件、電源、控制方式、材質與法規需求。
2. 將已知值、未知值、使用者提供值與工程假設分開列出。資料不足時可先做條件式初選，不得虛構 BNF 型錄數據。
3. 以 `H = H_static + h_f + h_minor + Δp/(ρg)` 建立揚程預算，註明單位與安全裕度。
4. 以 `P_h = ρgQH` 計算水力功率，再以泵浦及馬達效率估算軸功率與馬達需求。效率未知時提供範圍，不給假精度。
5. 檢查工作點是否接近 BEP、最低連續流量、NPSHa 與 NPSHr 裕度、材料相容性、馬達電源及啟動方式。
6. 僅在取得正式性能曲線或型錄後輸出候選產品；否則只輸出「水力需求規格」及待驗證清單。

## 證據閘門

- 未取得可識別版本與頻率的 APP Arwana／BNF 官方性能曲線時，禁止推測或輸出葉輪級數、精確馬達 kW 範圍、具體 BNF 型號、優先候選或「最合理型號」。
- 缺少官方曲線時，將結果標示為「水力需求規格，尚非產品選型」，只輸出 Q、H、介質、材料、電源、控制、NPSH 與待索取文件。
- 一般水力功率計算可作為需求估算，但不得反推出 BNF 級數或型號；泵浦效率未知時只列公式與所需效率資料。
- 任何產品候選都必須同時引用來源名稱、文件版本／日期、頻率、曲線頁面與 duty point；缺一即降級為未驗證假設。

## 輸出契約

- 設計條件表
- 計算與單位
- 水力需求規格；只有具備可引用的官方曲線時才能加入候選產品
- 風險與缺失資料
- 下一步驗證文件：性能曲線、NPSHr、尺寸圖、材質表、馬達資料

## 品質邊界

- 不把品牌型號、價格、交期或認證當作穩定事實；需要時查閱最新官方或供應商資料並附來源日期。
- 不以 AI 初選取代合格工程師、製造商或現場責任人的最終核准。
- 明確區分設計流量、額定流量、最大流量與測試條件。
- 結論不得使用「最合理」「優先」「約 N 級」等措辭包裝未經型錄支持的產品推測。
